# Triggers ↔ Galaxy: устройство и изменения 2026-09-09

Дополнено следующей серией исправлений: Param сохраняет авторский ScriptCode и
CustomType; ParameterType — ограничение VariableType. Операторы с собственным
телом остаются функциями, а тип фактического аргумента участвует в выводе
сквозных операторов. Регистрации событий используют порядок ParameterDef;
выражения пресетов разбираются в AST. Старые экспортируемые прямые обработчики
действий, сравнений и арифметики делегируют общему механизму шаблонов.

Конвертация работает с загруженными библиотеками и штатной Galaxy AST. Идентификатор
элемента — тройка `(library, type, id)`. ID отдельно не определяет элемент.
Новый основной путь действий не выбирает поведение по именам `WhileDo`,
`SetVariable`, `Comparison` или по известным ID NativeLib.

## Triggers → Galaxy

1. SAX-reader читает XML, сохраняя `ScriptCode`, роли `SubFuncType`, типы,
   флаги, значения и ссылки.
2. Перед генерацией проверяются ссылки и циклы в деревьях параметров/действий.
   Отсутствующая библиотека — ошибка с `context.conversionCode` и конкретной
   ссылкой. Конвертер больше не выдаёт вместо неизвестного дерева вызов
   с дополнительными исполняемыми аргументами `__MKX_SF__`.
3. `ScriptCode` раскрывается общим интерпретатором макросов. Параметры
   сопоставляются через `ParameterDef`; роли — через объявления `SubFuncType`.
   Сложные выражения подставляются с учётом скобок. Автопеременные получают
   область видимости шаблона и тип из объявления либо типа присваиваемого параметра.
4. Обычные функции, переменные, заголовок и инициализация собираются в Galaxy AST.
   Имена объявления, определения и вызова согласованы; коллизии имён разрешаются
   с использованием идентичности элементов.
5. Существующие `CustomScript` блоки сохраняются. Текст, похожий на макрос,
   внутри строк и комментариев не интерпретируется как макрос.
6. Иерархия категорий и подписи переносятся в неисполняемый комментарий
   `@modkit-editor-layout`. Он содержит только данные редактора и имена символов.

## Galaxy → Triggers

1. Парсер проверяет синтаксис. Обычные функции не обязаны иметь префиксы
   `lib…_gf_`, `gf_`, стандартные имена параметров или форматирование Blizzard.
2. Строятся таблицы функций, параметров, локальных и глобальных переменных,
   структур и зависимостей. Прототип отличается от функции с пустым телом.
3. Galaxy AST сопоставляется с `ScriptCode` загруженных определений. Названия
   действий не участвуют в структурном сопоставлении. Операторные позиции
   раскрываются из значений загруженных `Preset`, а не по имени параметра `op`.
4. Если подходящего определения нет, поддерживаемая конструкция AST получает
   редактируемое определение `FunctionDef` с `Template`, отдельными `ParamDef`
   и, для ветвей/циклов, `SubFuncType`. Это обычные элементы модели триггеров.
   Тело функции не сворачивается целиком в `CustomScript`.
5. Служебная оболочка триггера распознаётся по сочетанию соглашения об имени,
   сигнатуры и защитного блока. При извлечении условий проверяется форма
   блока целиком. Промежуточные `return`, присваивания и начальные значения
   сохраняются; снимается только завершающий `return true` оболочки.
6. Явные заголовки разделов вида «разделитель / название / разделитель» дают
   категории; прочие комментарии сохраняются как подписи. Если имеется
   метаданный комментарий Modkit, восстанавливаются вложенные категории
   и принадлежность именованных функций.
7. Результат сериализуется и заново читается. Сравниваются содержимое модели,
   флаги, параметры, роли, ссылки и корневые элементы. Контрольный Galaxy
   генерируется именно из перечитанного XML.

### Продолжение: инициализация и идентичность символов

Служебные функции больше не удаляются только по имени и наличию двух bool-флагов.
Проверяются целиком четыре функции инициализации, начальные значения флагов,
защитные блоки, порядок вызовов, регистрация триггеров и внешние ссылки на флаги.
Перенос в `Variable.initialValue` допускается для полностью распознанного набора
присваиваний литералов, включая циклы по всем элементам массива с локальными
счётчиками. Частичное распознавание не изменяет модель.

Смешанное тело с вызовами, частичной обработкой массива, зависимостью от состояния
или дополнительной логикой остаётся обычными структурными `FunctionDef`.
Это сохраняет команды и их порядок и не создаёт `__InitVariablesRaw`/CustomScript.
Старый специализированный разбор `convertInitVariablesBody` больше не вызывается
основным обратным конвертером.

Инициализатор триггера извлекается только если всё его тело представимо созданием
данного триггера, регистрацией событий из загруженных определений и включением/
отключением. Дополнительные команды сохраняют всю пару функций и handle как
обычные элементы. Совпадение имени handle с префиксом Blizzard само по себе
больше не удаляет объявление переменной.

Служебные символы генератора получают свободные имена при столкновении с
пользовательскими функциями; объявления, вызовы и зависимости используют один
механизм именования. ID обратного преобразования привязан к исходному символу:
`work` и `libTEST_gf_work` сохраняются раздельно, даже если их отображаемые имена
совпадают. Локальная функция также не изменяет объект определения загруженной
зависимости с совпадающим именем.

XML-reader сохраняет явный атрибут `Type` у ссылок `SubFunctionType`. Это
устраняет расхождение модели при повторном использовании шаблонов вложенных
ветвей; строгая сверка модели в публичной операции остаётся включённой.

При раскрытии `SUBFUNCS` с разделителем каждое дочернее выражение сохраняет
свои скобки. В частности, `(a || b) && c`, `(a + b) * c` и `a - (b - c)`
не превращаются в выражения с другой группировкой.

### Продолжение: восстановление шаблонов из произвольного AST

Обратное сопоставление теперь восстанавливает выражения `SUBFUNCS` с операторным
разделителем, списки аргументов и многооператорные действия. Вид разделителя
определяется парсером из загруженного `ScriptCode`. Для операторной цепочки
разворачивается только левая ветвь AST: `a - (b - c)` сохраняет вложенную правую
часть, а вызовы с побочными эффектами остаются в исходном порядке.

У последовательности команд должна быть восстанавливаемая граница. Например,
`begin(#PARAM(value)); #SUBFUNCS(body) end(#PARAM(value));` допускает пустое тело
и соседние независимые группы. Незакреплённое окончание `SUBFUNCS` не поглощает
остаток функции. Повторные параметры обязаны иметь одинаковый AST; совпадение,
которое захватило бы весь вход в один свой параметр, отклоняется без рекурсии.
Обычное тело функции без `Template` или макросов не считается встроенным действием.

Перед созданием ссылок конвертер повторно раскрывает найденный шаблон и сравнивает
его AST с исходным фрагментом. Это отклоняет ложные совпадения, включая пустой
список между запятыми и изменение группировки. Проверка типов сохраняет полную
идентичность структур/пресетов и использует типы объявленных полей структур.

Для многооператорного действия поддержано восстановление изолированных `AUTOVAR`.
Требуется локальная скалярная переменная с отдельным объявлением без начального
значения, совпадающим типом и отсутствием обращений вне сопоставленного фрагмента.
Анализ просматривает исходное тело функции, включая извлекаемые условия триггера.
Тип берётся из макроса либо формального параметра присваивания; обе стороны
используют общий разбор этих форм. Имена исходных временных переменных произвольны.

Если переменная используется в захваченных параметрах/дочерних командах, имеет
инициализатор, разделяется между действиями или конфликтует с областью вложенного
макроса, сохраняются обычные структурные команды и переменные. Две разные
автопеременные не могут подменить одну исходную переменную. Неизвестный тип и
буквальное имя структуры, требующее переименования при генерации, также не дают
основания удалять локальное объявление. Здесь `CustomScript` не требуется.

## Входы Modkit

- Trigger-сессия: `blizzard/sc2-triggers.trigger-to-galaxy` и
  `blizzard/sc2-triggers.galaxy-to-triggers`.
- Galaxy-сессия: новая операция `blizzard/galaxy.to-triggers`; исходником служит
  текущий документ. Во входе нужны `libraryId`, при необходимости `header`
  и `dependencyLibraries` в том же формате, что у Trigger-сессии.
- Операции возвращают данные и отчёт проверки; они не записывают карту.

## Исправленные ошибки

- Коллизии кэша выражений и поиск элемента по ID из чужой библиотеки/другого типа.
- Пропуск начальных значений локальных переменных и ранних выходов.
- Генерация отключённых действий, условий и событий.
- Потеря флагов функций, `SubFuncType`, `ValueGameType` и текста `ScriptCode` при XML-переходе.
- Разные имена одной функции в заголовке и теле; коллизии после очистки имени.
- Неиспользованные зависимости в публичном обратном преобразовании.
- Потеря рукописных функций без префиксов редактора.
- Неверные ссылки на поля структур, индексы и параметры-функции при генерации.
- Замена неизвестного шаблона пустым телом или фиктивным значением возврата.
- Зависимость кодирования метаданных от глобального Node `Buffer`.
- Проверка XML только по количеству элементов вместо их содержимого.

## Границы текущей реализации

Это преобразователь в библиотеку триггеров, не самостоятельный Galaxy runtime.
Для авторских Triggers по умолчанию генерируется библиотечная инициализация.
Для сохранённых исходных функций предусмотрен режим `initialization: 'preserve'`:
он не добавляет второй набор стартовых функций, а начальные значения глобальных
переменных остаются в объявлениях. Произвольный набор `include` не является
автоматически разрешённым проектом.
Сравнение канонического Galaxy остаётся консервативным: переименование локальных
переменных или другая форма объявления могут дать `partial`, даже когда
соответствующая структура восстановлена.

Поддержаны `INITAUTOVAR`, условное включение `IFHAVESUBFUNCS`,
`IFSUBFUNC(notfirst,...)` и выбор области `AUTOVAR` через `parent`/`ancestor`.
Тип временной переменной выводится из параметра, литерала или загруженного
объявления вызываемой функции. Неизвестные типы не подменяются `int`.
Другие редкие макросы, включая `PRESETIDENT`, требуют отдельной проверки семантики.
Неподдерживаемый макрос выдаёт диагностику; он не заменяется догадкой или пустым
кодом. Не все многострочные шаблоны с автопеременными реконструируются в одно
исходное высокоуровневое действие: в таких случаях сохраняется структура
поддерживаемых операторов Galaxy. Старые специализированные вспомогательные
распознаватели ещё присутствуют в кодовой базе как прежние вспомогательные API;
основной путь инициализации их больше не использует.

Распознавание служебной инициализации намеренно ограничено доказуемыми случаями.
Вызовы с побочными эффектами, символические границы массивов, инициализация полей
структур и явно заданный порядок запуска нескольких зависимостей пока сохраняются
в виде функций. Восстановление исходных GUI-начальных значений для этих случаев
требует дополнительного анализа зависимостей и порядка исполнения. Сохранение
функций и AST не является подтверждением эквивалентного запуска всего проекта.
Режим сохранения и явная точка входа задают контракт генерации отдельного скрипта;
порядок загрузки внешних include и выполнение в движке требуют отдельной проверки.

Без комментариев/метаданных исходная иерархия папок не выводится однозначно.
Подписи сохраняют текст, но не исходную позицию каждого комментария внутри
функции. Метаданные Modkit проверены на повторном преобразовании Modkit;
сохранение их внешними форматтерами и редактором Blizzard не проверено.

Новые синтетические определения и результат в целом пока не проверялись
загрузкой, сохранением и компиляцией в SC2 Editor. Проверки XML и AST не
заменяют эту проверку. Для редкого неподдерживаемого синтаксиса сохраняется
явная ошибка, вместо потенциально неверного `CustomScript` с утраченными связями.

## Проверка

```powershell
pnpm exec tsc -p starcraft2/tsconfig.trigger-conversion.json --noEmit false
pnpm exec vitest run --config starcraft2/test/vitest.trigger-conversion.config.mjs
```

Новый набор покрывает произвольные имена, пустые функции, ранние выходы,
приоритет операций, циклы, структуры, зависимости, коллизии ID,
отключённые действия, XML-флаги/роли, сохранение `ScriptCode`, папки и комментарии,
операторные пресеты, область автопеременных и работу без `Buffer`.
Конфигурация также включает существующие тесты `g2t-*` и `ttg-*`.
Результат проверки 2026-09-08 после расширенного корпуса: 333 теста проходят без пропусков,
включая 35 новых сценариев восстановления шаблонов через публичную операцию,
сериализацию, перечитывание XML и повторную генерацию Galaxy. Проверка TypeScript
через `tsconfig.trigger-conversion.json` проходит; она охватывает публичные входы
обоих конвертеров и их зависимости. Полная
сборка при последнем запуске сообщила об ошибках типов в соседнем

Регрессия `g2t-init-fold` теперь использует
минимальные объявления NativeLib и проверяет сохранение смешанной инициализации,
а не зависит от установленного корпуса игровых данных.

### Проверка на авторских модах

Дополнительные 29 синтетических регрессий получены при исследовании SCEvo Core,
Legacy, AllRaces и рукописного BuildAI. Игровые файлы в тесты не копируются.
Исправлены потеря пустых значений XML и признака массива, чтение `Comment`,
элементов `CustomScript` с `InitFunc`, типов из грамматики Galaxy и локальных
констант. Инициализаторы пользовательских скриптов вызываются в порядке дерева
после переменных и перед триггерами. Отключённые элементы не выполняются.

Бинарные `FlagOperator` без `ScriptCode` распознаются по трём упорядоченным
параметрам и пресету допустимых операторных токенов. Имя определения не выбирает
операцию. GUI-оператор не подменяет одноимённую вызываемую функцию при обратном
преобразовании. `PresetGenConstVar` сохраняется в XML, константы получают
объявления и квалифицированные ссылки. Прямые параметры и вложенные вызовы
используют общее разрешение пресетов, в том числе из зависимостей. Явное значение
Galaxy имеет приоритет перед генерируемым именем: штатный заголовок зависимости
может не экспортировать отдельную константу для такого пресета. Значение без
скаляра и без генерации констант отклоняется: XML ID не является Galaxy-значением.
Прототипы сохраняют полные имена.

Размер массива в Galaxy означает длину, а в Trigger XML — включённую верхнюю
границу. Поддерживаются положительные целые литералы и ссылки вида `N + 1`
(также `1 + N`). Другие выражения, включая голое `N`, пока отклоняются с
`ARRAY_DIMENSION`: прежнее преобразование `N` в `N + 1` меняло семантику.
Следующее расширение должно вычислять константные выражения с учётом области
видимости либо хранить точное выражение границы в подтверждённой схеме редактора.

Опциональный скрипт `scripts/audit-trigger-corpus.mjs` принимает локальный
JSON-манифест и отдельный каталог результатов. В манифесте задаются
`readOnlyRoots`, `dependencies` (пути `triggers`, необязательный `strings`) и
`cases` (`name`, `libraryId`, `triggers`, `strings`, `script`, `header`,
необязательные зависимости конкретного случая). Можно отключить фазы через
`forward`, `reverse` или `roundTrip: false`.

```powershell
node scripts/audit-trigger-corpus.mjs C:/work/corpus.json C:/work/audit-output
```

Скрипт пишет результат вне заданных корней исходников и проверяет SHA-256 всех
прочитанных файлов до и после работы. Он сохраняет XML, Galaxy, диагностику,
строгую сверку XML-модели и сравнение AST функций. `ok` фазы означает завершение
операции без ошибок парсера и подтверждённых ошибок деклараций результата;
это не проверка выполнения в игре. Неразрешённые внешние объявления отражаются
отдельным статусом `incomplete`.
`completeness: complete` прямой операции также не означает совпадения с Galaxy,
который ранее сгенерировал редактор: для этого в отчёте есть отдельное сравнение.

У Core обнаружен контейнер вложенных действий без `ScriptCode` в NativeLib:
прямая конвертация останавливается с `UNSUPPORTED_TEMPLATE`. У AllRaces есть
ссылка на функцию, отсутствующую в предоставленной версии зависимости Core.
Случаи не обходятся таблицей имён или ID. Обратное преобразование реальных
скриптов остаётся `partial`; XML и синтаксические проверки не доказывают
сохранение запуска, глобальной инициализации или модификаторов функций.

### Сохранение запуска и проверка объявлений

При наличии сохранённого стартового набора проверяются сигнатура и защитный
блок `InitLib`, ссылки на функции этапов, отсутствие повторов и порядок этапов.
Тела этапов не сворачиваются и не заменяются. Такой путь автоматически выбирается
для распознанной сохранённой схемы; произвольные имена поддерживаются через
необязательный `entryPoint`. Он должен указывать на определённую функцию
`void` без параметров. Несколько подходящих стартовых наборов дают явную ошибку.

Для исходника без узнаваемого библиотечного запуска публичная обратная операция
выбирает сохранение функций без придумывания точки входа. Её результат может
содержать `output.generationOptions`. Этот объект нужно сохранять вместе с XML
и передавать при последующем преобразовании; чистый Trigger XML не кодирует
контракт запуска произвольного исходного файла. Это отдельные параметры
генератора, не скрытый исполняемый текст и не расширение схемы Blizzard.

```js
const reversed = await convertGalaxyToTriggers({
  libraryId: 'Example', script, header, entryPoint: 'LaunchScenario',
});
const forward = await convertTriggersToGalaxy(reversed.output.triggerData, {
  ...reversed.output.generationOptions,
  dependencyLibraries,
  galaxyDeclarations: [{ fileName: 'dependency.galaxy', text: declarations }],
});
```

Параметр `initialization: 'library'` явно выбирает генерацию библиотечного запуска;
с `entryPoint` он несовместим. `initialization: 'preserve'` с отдельными элементами
`CustomScript.InitFunc` пока отклоняется: нельзя молча пропустить их запуск или
вставить его в произвольное место. Порядок глобальных объявлений следует корневым
ссылкам/дереву модели, а не сортировке XML-элементов по ID.

Подготовка локальных переменных перед условиями триггера теперь разбирается
до самих условий. Если она представима упорядоченными начальными значениями,
переменные инициализируются до `testConds` и `runActions`. Нестандартный префикс
сохраняет callback как обычную структурную `FunctionDef`, без CustomScript.
Константы пресетов восстанавливаются только из подходящих `const`-объявлений
с явными скалярными значениями; похожее имя изменяемой переменной не удаляет её.

Скрипт и заголовок проверяются в общем контексте с переданными
`galaxyDeclarations`. Проверяются разрешение символов, конфликты деклараций,
число/типы аргументов, возвращаемые значения, присваивания, области локальных
переменных, поля структур и индексы массивов. Проверка не выполняет файловый I/O
и не ищет объявления по предполагаемым именам игровых функций.

`fidelity.verification.galaxyValidation` содержит `status`, `errors`,
`unresolvedSymbols`, `uncheckedTypes` и сведения об ограничении диагностики.
`passed` означает прохождение реализованных проверок; `incomplete` — нехватку
объявлений или типов; `failed` — обнаруженную ошибку. При `strictSymbols: true`
неразрешённые имена становятся ошибками. Потеря ранее разрешённого объявления
после обратного преобразования всегда даёт `galaxy-lost-binding` и `failed`.
Это не полноценный linker, проверка всех правил Galaxy или подтверждение
эквивалентного выполнения. `completeness` описывает конвертацию; состояние
контекста объявлений нужно читать отдельно.

Для очень больших документов обратный Galaxy-проход можно вынести в отдельный
процесс: `verification: 'semantic'` завершает операцию после сериализации и
точного повторного разбора TriggerData. В отчёте такой запуск явно помечается
`galaxyValidation.deferred: true`, канонические результаты равны `null`, а
`completeness` остаётся `partial`. Значение по умолчанию — `verification: 'full'`;
оно по-прежнему выполняет Galaxy→Triggers→Galaxy и проверку привязок в одном
процессе. Отложенный режим уменьшает одновременный объём живых AST/моделей, но
не является доказательством корректности обратного Galaxy до отдельного прохода.

Добавлены 22 проверки запуска и объявлений. Ограниченный тестовый исполнитель
AST сравнивает порядок вызовов/присваиваний, начальные значения глобальных
переменных и повторный вызов защищённого запуска; он не является игровым runtime.
Корпусный аудит принимает `galaxyDeclarations` и `generationOptions` в манифесте,
сохраняет `*-reverse.generation.json` и использует его при следующем проходе.
AllRaces исключён из дальнейших прогонов по указанию пользователя.

### Расширенный корпус: SCEvoComplete2, Coop, MISS2 и OblivionExpress

Ссылка `SubFuncType.FunctionDef` теперь сохраняется при чтении и записи XML.
По ней и шаблону дочерней функции можно восстановить неявный контейнер цепочки
ветвей: контейнер должен иметь единственную роль действий, не иметь собственного
тела/параметров и ограничивать дочернее определение. Первый и последующий варианты
`IFSUBFUNC(notfirst,...)` проверяются парсером как `if` и связанная ветвь `else if`.
Имена и ID функций не участвуют в выборе этого правила. Неподходящий дочерний
вызов даёт `TEMPLATE_SUBFUNCTION_DEFINITION`; произвольное дерево не разворачивается.

Пустые группы выражений с разделителем `&&` или `||` получают соответственно
`true` или `false`. Оператор определяется из AST разделителя. Вложенные фрагменты
с комментариями раскрываются до проверки синтаксиса родительского шаблона;
завершающий строковый комментарий сохраняет перевод строки.

Глобальные callback `gt_...` пока сохраняются обычными структурными функциями:
библиотечный Trigger-элемент менял бы их имена, оставляя прежние вызовы и строковые
ссылки `TriggerCreate`. Это относится и к MapScript. Для возврата таких callback
в GUI Trigger требуется выражаемое в модели пространство имён карты. CustomScript
для этой задачи не создаётся. Точные имена нативных функций имеют приоритет перед
псевдонимами одноимённых GUI-обёрток с другими сигнатурами.

Расширенный аудит включает 13 библиотек/карту и четыре дополнительных скрипта
(один файл оказался пустым). Для карты контекст COMI берётся из указанной в
DocumentInfo зависимости ARC2: одноимённая библиотека Coop имеет другое API.
Полные документы Coop и ARC2 превышают ограничение входа в 32 МиБ. Обратная
конвертация отдельных Galaxy-файлов проверялась также отдельно, с объявлениями
зависимостей; это не проверка полной загрузки модов.

Остаются неподдержанные одноаргументные операторы GUI-типов, `structref`/typedef,
ссылки на внешние границы массивов без загруженной модели зависимости и медленная
обратная конвертация большого Core. Нельзя считать неизвестные зависимости
разрешёнными или полную эквивалентность выполнения подтверждённой.

## Следующий этап: Editor / Ghidra / runtime

Пользователь разрешил анализ SC2 Editor EXE. В этом изменении Ghidra не запускалась
и код из EXE не извлекался. Полезный порядок дальнейшей работы:

1. Зафиксировать версию и хеш EXE; найти обработчики строк `ScriptCode`,
   `PARAM`, `SUBFUNCS`, `AUTOVAR`, `INITAUTOVAR`, `DEFRETURN`, `SMARTBREAK`.
   Восстановить обработку типов, областей видимости, временных переменных и ошибок.
2. Построить маленький корпус библиотек и получать штатный Galaxy через редактор.
   Сравнивать AST, связи и результаты компиляции, а не только текст или длину файлов.
3. Найти границу штатного генератора Triggers → Galaxy. Вызов найденной функции
   из внешнего процесса требует проверки ABI, владения памятью и зависимостей
   от объектов документа, локализации и загруженных библиотек. Сам адрес функции
   не доказывает, что её можно использовать отдельно от редактора.
4. Для собственного runtime разделить семантику языка, модель выполнения
   и API игрового окружения. Существующая Galaxy AST может служить входом
   интерпретатора или компилятора в промежуточный код. Native API нужно
   связывать с таблицей объявлений загруженного проекта; игровой мир, события
   и планировщик потребуют отдельной реализации.

Сначала штатный генератор редактора полезен как эталон проверки конвертера.
Выбор между адаптером к редактору и самостоятельным runtime следует делать
после установления реальных зависимостей, а не на основании предположения,
что одну функцию из EXE удастся перенести без окружения.


## Исправления по аудиту 2026-09-09

`PresetInteger` сохраняется в модели и XML. Если значение не задано, его число
берётся из порядка ссылок `Item` родителя, включая генерацию констант в заголовке.
ARGB-значения редактора преобразуются в `Color`/`ColorWithAlpha`; некорректный
литерал цвета вызывает ошибку, а не превращается в строку.

Оператор без `ScriptCode` с одним параметром может быть раскрыт как тождественное
выражение только при разных GUI-типах и одинаковом разрешённом типе Galaxy.
Неопределённые `any`/`sameas` исключены. Преобразование `string` → `text` и сужение
числа не угадываются. Таблицы ID и имён операторов не добавлены.

Примитивные типы определяет грамматика Galaxy. Они имеют приоритет над таблицей
псевдонимов GUI, поэтому `soundlink` сохраняет собственный тип. Неизвестный узел
типа больше не подменяется на `int`. Полная поддержка `structref` и typedef ещё
не реализована; ошибка конверсии в таком случае остаётся явной.

При нескольких библиотеках в одном TriggerData обязателен `libraryId`. Операция
по-прежнему возвращает одну выбранную библиотеку, а остальные использует как
контекст. Это не пакетный экспорт документа.

Валидатор получает доступные сигнатуры из загруженных Trigger-библиотек.
Явно переданные Galaxy-объявления приоритетнее производных сигнатур. Неопределённые
типы не получают выдуманных сигнатур. Ошибка самого валидатора отмечается
`galaxy-validation-failed` и `validationCompleted: false`, сохраняя полученный
результат конверсии. `incomplete` не означает, что внешние символы проверены.

Разбор XML для анализа повторно использует уже прочитанные документы. Компиляция
шаблонов зависимостей кэшируется между телами функций в рамках одного контекста
конверсии. Общего межоперационного кэша загруженных проектов пока нет.

### Настраиваемые бюджеты

Публичные функции принимают объект `limits`:

| Поле | По умолчанию | Максимум |
|---|---:|---:|
| `maxInputBytes` | 32 МиБ | 128 МиБ |
| `maxDependencyBytes` | 32 МиБ | 256 МиБ |
| `maxLibraryElements` | 100 000 | 1 000 000 |
| `maxTotalElements` | 500 000 | 2 000 000 |

Размер зависимостей ограничивается и для отдельного документа, и в сумме.
Проверки количества элементов отдельной библиотеки и всей модели разделены.
Неизвестные ключи, неположительные и чрезмерные значения отклоняются.
`maxOutputBytes` остаётся отдельным параметром: 16 МиБ по умолчанию, до 64 МиБ.
Пределы для Galaxy-объявлений и количества документов не отменены.
Увеличение бюджета не разрешает конфликтующие версии одной библиотеки и не
добавляет поддержку отсутствующих языковых конструкций.

Корпусный скрипт `scripts/audit-trigger-corpus.mjs` принимает `limits` из манифеста
или отдельного случая. Пустой список случаев теперь является ошибкой.


Параметры обычных и вложенных вызовов используют одну реализацию `ttg-params`;
старый вход в `ttg-convert` делегирует ей. Шаблон из одного параметра исключается
из обратного индекса заранее: у него нет синтаксиса, который можно восстановить.
Это убирает повторную сериализацию всего выражения ради заведомо отклоняемого
совпадения; прямое раскрытие такого шаблона остаётся доступным.


При прямом преобразовании контекст хранит индексы коллизий имён функций и имён
глобальных переменных загруженных библиотек. Это устраняет полный обход библиотеки
для каждого вызова/аргумента и каждой производной сигнатуры валидатора. Индексы
не переживают новый вызов конвертера: правки исходной модели учитываются заново.


Не допускается стирать собственное тело или Native-реализацию оператора ради
тождественного преобразования типов. Отсутствующий возвращаемый тип Native-функции
в GUI-метаданных также не означает `void`: для проверки такой сигнатуры нужны
Galaxy-объявления. Основной XML разбирается с переиспользованием результата для
выбора библиотеки, анализа и подсчёта типов. При обратном сопоставлении тип
выражения вычисляется один раз для набора кандидатов, без изменения связей AST.
