# Источники CASC и Battle.net

Оба desktop-хоста используют общий выбор источников: `@modkit/ui/content-sources`.
В Electron это кнопка **Источники…** над деревом файлов. В VS Code — команда
**Modkit: Источники содержимого (локальные / Battle.net)…** (`modkit.contentSources`).

- **Установленная игра** открывает локальный CASC через существующий codec namespace.
  Electron предлагает каталог установки; VS Code использует выбор установленной игры.
- **Кеш Battle.net — карты и моды** читает локальный `Battle.net/Cache` без сети и входа.
  Корень — плоский список публикаций с названиями из `.s2mh` и связанного `.s2ml`
  (приоритет ruRU, затем enUS). Регион, версия и суффикс хеша различают одноимённые записи.
  Внутри доступны `metadata.json`, исходные `Components` и `Content`, если `.s2ma` есть локально.
  Метаданные включают исходное имя пакета, локализованное описание, ID, версию и ссылки
  на компоненты. Хеши проверяются при чтении. Отсутствие архива, повреждённый заголовок
  и компонент без заголовка отображаются явно; сетевой запрос для них не выполняется.
  Заголовки очередей подбора (`.s2qh`, в них ладдерные маппулы) и их строки (`.s2ql`) открываются
  своими кодеками; живой список очередей — `describeQueues`, см. [matchmaking-queues.md](matchmaking-queues.md).
- **StarCraft II — Maps и Mods** открывает только эти два подкаталога выбранной установки.
  Обычные папки сохраняют структуру, `.SC2Map` / `.SC2Mod` / `.SC2Campaign` в MPQ
  раскрываются как каталоги, распакованные проекты доступны таким же образом.
- **StarCraft II — данные игрока и настройки** открывает `Documents/StarCraft II`.
  Банки, сохранения, реплеи, профили хоткеев и Variables.txt остаются файлами и открываются
  существующими просмотрщиками Modkit. Эта интеграция добавляет доступ, а не новый декодер
  произвольного состояния `.SC2Save`. Исходные папки не изменяются; ссылки наружу не обходятся.
- **StarCraft II — кеш данных карт** открывает отдельный
  `ProgramData/Blizzard Entertainment/StarCraft II/Maps/Cache` как read-only дерево. Это
  производные файлы карт редактора/игры; они не смешиваются с публикациями из Battle.net cache.
  Физические каталоги `<hash>.s2ma` показываются как `.SC2Map` или `.SC2Mod`. Исходное имя
  и тип берутся из того же индекса Battle.net; если заголовка нет, отображается `.SC2Map`
  с частью хеша, а внутренние операции прозрачно переводятся обратно в физический путь.
- **Аккаунт + сервер** показывает опубликованные карты и моды выбранного SC2-профиля.
  Можно одновременно подключить несколько аккаунтов и регионы NA (`us`), EU, KR.
- **Public mods** — отдельный список сохранённых публичных публикаций в каждом регионе.
  «Найти и добавить публичный мод» выполняет поиск на Battle.net через выбранную сессию,
  после чего пользователь выбирает конкретный результат. Это список добавленных модов,
  а не предварительно скачанный полный каталог Blizzard.

При раскрытии мода VFS получает его `.s2mh`, проверяет ссылку на `.s2ma`, скачивает MPQ
и проверяет SHA-256. Затем дерево и файлы доступны из дискового кеша. Каталог корня и
поиск не скачивают архивы. Файлы открываются в обычных представлениях Modkit только для
чтения. Максимальный размер одного файла для предпросмотра — 64 MiB.

## Вход и выход

Выберите «Добавить аккаунт / регион», сервер и новый либо уже подключённый аккаунт.
Официальная страница Blizzard открывается в отдельном окне Electron. Пароли и коды
вводятся на этой странице. Возврат `localhost:0/?ST=…` перехватывается внутри окна:
локальный HTTP-сервер не нужен, адрес не нужно копировать в приложение или чат.

После веб-входа backend устанавливает native SC2-сессию и проверяет регион и профиль.
Каждое подключение использует отдельный native worker. Добавление региона существующему
аккаунту проверяет идентификатор вошедшего аккаунта.

Окно входа получает один постоянный профиль на машину: `<stateDirectory>/battlenet-login/account`.
Аккаунт Battle.net не региональный — редактор игры тоже логинится один раз и публикует туда, куда
указан, — поэтому второй и третий регион подключаются без ввода пароля. Отмеченный на странице
Blizzard пункт «оставаться в сети» работает; свои токены Modkit на диск не пишет. Профиль,
оставшийся от прежней раскладки «каталог на регион», принимается как этот же вход.
Окно показывается, только если вход действительно нужен: сохранённая сессия отвечает
перенаправлением, и тогда окна не видно вовсе.
«Отключить аккаунт» удаляет этот профиль — машина выходит из Battle.net, а не из одного сервера;
закрытие приложения только рвёт соединения и вход не забывает. Смена аккаунта в регионе начинается
с выхода. Backend без хранения (`forget()` не реализован) ведёт себя как раньше.

«Отключить аккаунт / регион» закрывает выбранную сессию и делает её личное хранилище
недоступным. Другие подключения продолжают работать. Сохранённые публичные версии
доступны через depot и после выхода. Их метаданные находятся в `state/public-mods-v1.json`.
Удаление мода из этого списка не удаляет публикацию с Blizzard.

## Подключение текущего native backend

Локальные адаптеры доступны независимо: `@modkit/blizzard-starcraft2/sources/cache/node`
экспортирует `BattleNetCacheSource`, `sources/folder/node` — `Sc2FolderSource`, а
`sources/local/node` — самостоятельную фабрику `createContentSources`. Последняя не
требует Python, native decoder или авторизации. Её можно указать как `module` в JSON
хоста для полностью локального режима. Desktop Battle.net factory объединяет те же
источники с онлайн-каталогом.

VS Code автоматически находит эту фабрику в установленном расширении StarCraft II. Он добавляет
выбранную через Sources установку как `installationDirectory`, а Battle.net cache, SC2 Maps Cache,
Documents и Editor Wizards фабрика обнаруживает по стандартным Windows-путям. Ручной `provider.json` для
локального режима больше не нужен. Без выбранной установки её Maps/Mods не добавляются.

Явные пути по-прежнему поддержаны доверенной конфигурацией: `battleNetCacheDirectory`,
`sc2MapsCacheDirectory`, `installationDirectory`, `documentsDirectory`, язык метаданных — `locale`.
Предпросмотр файла ограничен 64 MiB, загрузка одного MPQ — 256 MiB. Локальные провайдеры
не следуют filesystem links и не позволяют выйти из своего корня.
Локальные корни и файлы можно показать в Проводнике через общий `resolveLocalPath`:
это относится к установке, Maps/Mods, Documents/настройкам, мастерам редактора,
SC2 Maps Cache и исходным `.s2ma`-компонентам Battle.net cache. Виртуальные файлы внутри
упакованного MPQ показывают физический пакет, которому они принадлежат.

Online-интеграция требует явно заданного native runtime и ещё не является автономным
распространяемым пакетом. Хост загружает JSON по абсолютному пути из настройки VS Code
`modkit.contentSourceConfig` или переменной `MODKIT_CONTENT_SOURCE_CONFIG`.
Пример подготовлен в `artifacts/sc2-publishing-research/content-source-provider.local.json`
родительского workspace:

Для этой рабочей копии `artifacts/sc2-publishing-research/start-content-sources.ps1`
запускает готовый Electron. Аргумент `-App VSCode` устанавливает собранный
`modkit-core/artifacts/content-sources-ui/modkit-battlenet-delete.vsix` в отдельный
локальный профиль VS Code и открывает окно с настроенным backend. Обычные профили
приложений при таком запуске не изменяются.

```json
{
  "module": "C:/workspace/modkit-extensions-blizzard/starcraft2/dist/modules/game/battlenet/desktop/desktop-backend.js",
  "options": {
    "battleNetCacheDirectory": "C:/ProgramData/Blizzard Entertainment/Battle.net/Cache",
    "installationDirectory": "C:/Apps/StarCraft II",
    "documentsDirectory": "C:/Users/Admin/Documents/StarCraft II",
    "locale": "ruRU",
    "researchDirectory": "C:/workspace/artifacts/sc2-publishing-research",
    "pythonExecutable": "C:/workspace/artifacts/sc2-publishing-research/.venv/Scripts/python.exe",
    "electronExecutable": "C:/workspace/modkit-core/apps/electron/node_modules/electron/dist/electron.exe"
  }
}
```

Также можно разместить `provider.json` в каталоге `content-sources` внутри `userData`
Electron или `globalStorageUri` VS Code. Этот файл задаёт исполняемый модуль и должен
принадлежать пользователю/установщику. Он не считывается из открытой карты или webview.
Каталоги `cache` и `state` назначает хост, отдельно для каждого приложения.
При отсутствии backend локальные источники остаются доступны.

Runtime требует Python-окружение исследовательского прототипа, извлечённые descriptors
и BSN metadata, собранный `native-decoder`, native public parameters и вспомогательные
модули рядом с `content_worker.py`. Этот вариант рассчитан на Windows и проверенный
протокол редактора build 97563; обновление игры может потребовать обновления протокола.

## Границы текущей реализации

- Live-проверка проведена в NA: вход, 50 собственных публикаций, 10 корневых записей
  Mod11, чтение DocumentInfo (245 байт), поиск Direct Strike, добавление в публичный
  список и выход. EU/KR реализованы как отдельные регионы; live-проверка там не проведена.
- Требуется один игровой аккаунт S2 и один SC2-профиль в выбранном регионе. Выбор среди
  нескольких лицензий/профилей внутри одного Blizzard-аккаунта ещё не реализован.
- Публичный поиск использует восстановленную секцию поиска по имени. Если сервер
  возвращает неполную страницу, backend требует более точного названия.
- Поддержаны MPQ-компоненты. Standard Data, восстановление неизвестных имён и сборка
  полной карты из произвольного набора зависимостей не подменяются фиктивной `.SC2Map`.
- Desktop backend и оба меню подключают native публикацию **подготовленного пакета**.
  Генератор полного пакета из произвольного `.SC2Map/.SC2Mod` пока отсутствует.
  Нельзя взять заголовок другой карты или заменить в нём только хеш архива: зависимости,
  игровые варианты, namespace атрибутов и локализации должны соответствовать документу.

## Удаление собственной публикации

Поиск по имени работает через «Найти и добавить публичный мод». Выберите аккаунт и
регион, найдите название, добавьте результат в «Public mods», затем откройте этот
источник. Архив загружается при раскрытии мода, проверяется по SHA-256 и кешируется;
внутренние файлы доступны через VFS. Сама выдача поиска не скачивает архивы.

Операция «Удалить свою публикацию из Battle.net» отделена от «Убрать сохранённый
публичный мод», которая удаляет только локальную закладку. Удаление выбирает аккаунт,
регион и собственную публикацию из свежего каталога. Перед отправкой UI показывает
название, ID и версию, аккаунт и регион; по умолчанию предлагается отмена.

Провайдеры `BattleNetVfsProvider` и `BattleNetAccountsProvider` предоставляют
`deletePublication({ region, publication, operationId?, signal? })`; для accounts
дополнительно обязателен `accountId`. Desktop facade использует одноразовые токены
`deletionCandidates(connectionId)` → `deletePublication(selectionId)`. Токены из
публичного поиска не подходят для удаления; выход из аккаунта их отзывает.

Backend реализует native `S2Map.Unlink`, а не физическое стирание depot-компонентов.
Он перечитывает полный авторский каталог и проверяет `linked`, ID, версию, имя,
тип и header hash, сохраняет журнал **до** отправки, проверяет commandId ответа и
затем снова перечитывает каталог. `status: "unlinked"` возвращается только когда
публикация отсутствует в каталоге либо явно имеет `linked: false`.
Сохранённые публичные закладки и локальные/серверные кеш-копии могут остаться доступны.
Неизвестный исход не повторяется автоматически, даже с новым operationId для той же
версии. Публикация и удаление взаимно исключаются для одной сессии/региона.

Wire request/response проверены в Unicorn на 12 синтетических случаях против
неизменяемого образа редактора build 97563 (`emulate_unlink.py`). Native transaction,
проверка владения, stale-version, потеря подтверждения и региональная привязка покрыты
offline тестами (`test_content_deletion.py`, `battlenet-deletion.test.mjs`). Реальные
публикации в рамках реализации удаления не удалялись; live-подтверждение Unlink пока
отсутствует. Общий UI проверяется в Electron с mock backend.

## Публикация подготовленного пакета

В меню «Источники» выберите «Опубликовать подготовленный пакет карты/мода», затем
аккаунт/сервер, полный путь сохранённого архива и `.modkit-publish.json`. Это собственный
формат Modkit, не формат экспорта `.SC2Publish` редактора. Окно проверки показывает
получателя, регион, create/update, видимость, блокировку, размер и SHA-256.
Только выбор «Опубликовать» запускает отправку; отмена не вызывает native публикацию.

Manifest schema 1 содержит `region` (`us/eu/kr`), `name`, `locale`, `kind` (`map/mod`),
`archiveSha256`, `target` (`{mode:"create"}` либо `{mode:"update",id,expectedVersion}`),
`visibility` (`private/public`), `locked`, `header: {file,sha256}`, `locales: [{file,sha256}]`,
необязательные `visuals: [{file,sha256}]` и `metadata`. Пути компонентов относительны
каталогу manifest; выход из него запрещён. Тип `PreparedPublicationManifest` находится
в `desktop-publication.ts`.

`metadata` содержит подготовленные поля `m_isExtensionMod`, `m_isUndependable`,
`m_isSkipInitialDownload`, `m_isMelee`, `m_isCluster`, `m_isHiddenLobby`,
`m_clusterParent`, `m_labels`, `m_categoryMask`. Пока поддержаны пустые labels и null
clusterParent. Идентификатор новой версии, авторские настройки и locked берутся из
проверенного запроса/серверной сессии, а не из произвольных полей metadata.

Заголовок `.s2mh` должен быть полностью скомпилирован для выбранного региона и иметь
namespace, возвращаемый native PrePublish для этого имени. Backend проверяет ссылки
на архив, локализации и изображения; поддержаны `.s2ma/.s2mh/.s2ml/.s2mv`.
Неизвестные или недостающие компоненты отвергаются до выделения версии. Общий предел
пакета — 256 MiB. Поддержка create в протоколе не означает, что Modkit уже умеет
скомпилировать первую публикацию произвольной карты.

Последовательность: проверка снимка → PrePublish и expectedVersion → журнал перед
Publish → allocation → Cache PublishListDeclare → gateway uploads с проверкой
подлинности сервера → новый native InfoRequest с latest-selector и проверкой точного
ID/версии/header hash/названия/флагов. Только после этого возвращается `published`.
Журнал в `state/publications/<account-profile-region hash>` не содержит credentials.
При неизвестном исходе он блокирует повторное выделение версии, в том числе с новым
operationId для того же запроса. Автоматический resume/reconcile ещё не реализован;
такую операцию нужно проверить по журналу и серверному каталогу, не удалять журнал
и не повторять отправку вслепую. Завершение региональной сессии отменяет её операции.

NA/EU/KR проходят один путь. Убрано фиксированное `US` из результата native каталога;
регион определяется подтверждённым SC2-профилем. Равенство поведения проверено
транспортными тестами; реальные EU/KR входы и публикации этим не заменяются.

## Проверки

В репозитории Blizzard: `pnpm --filter @modkit/blizzard-starcraft2 test:battlenet`.
Для двух тестов настоящего MPQ задайте `MODKIT_BATTLENET_TEST_ARCHIVE` абсолютным путём
к сохранённому архиву. Проверки публикации используют backend-фикстуру и ничего не публикуют.

В core: `node apps/electron/test-e2e/content-sources.mjs` после сборки Electron проверяет
настоящие renderer/preload/main, выбор источника, дерево и открытие файла с тестовым
backend без входа в Blizzard. `check_content_sources.mjs --live` в исследовательском
runtime отдельно проверяет настоящий сервис с интерактивным входом.

`test_content_publisher.py` проверяет транзакцию, региональную привязку, потерю
подтверждения, обрыв загрузки и защиту от повторного allocation без сети.
`check_prepared_publication.py` создаёт и проверяет подготовленный пакет уже известного
Mod11 из локальных компонентов (включая s2mv); это тестовая фикстура, а не общий
генератор пакетов. Новый desktop upload-hook пока не прошёл live-публикацию.
Electron smoke дополнительно проходит окно проверки публикации и подтверждение
через mock backend с выбранным KR; он ничего не отправляет Blizzard.

`check_local_sources.mjs` проверяет локальные источники без сети. Проверка 8 сентября
2026 года: 1054 заголовка, 693 русских названия, 0 неразобранных заголовков, 336 записей
с локальным архивным компонентом (94 уникальных `.s2ma` в кеше). Проверено чтение MPQ
и банков; найдены 38 SC2Bank, 11 SC2Save, 11 SC2Replay и 2 SC2Hotkeys. Эти числа описывают
текущий диск и не зашиты в провайдер. `check_local_sources_ui.mjs` проверяет эти же
источники через обычный интерфейс Electron.
