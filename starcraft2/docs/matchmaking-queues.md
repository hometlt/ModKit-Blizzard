# Очереди подбора и ладдерные маппулы (`.s2qh`, `.s2ql`)

Пул карт ладдера — это не отдельный список, а часть **заголовка очереди подбора** (`.s2qh`,
`Battlenet::MatchMaker::Header`). У каждой очереди (1v1, 2v2, кооператив, турнир…) свой заголовок.
Сервис игры называет его 40-байтным хэндлом кэша; сам файл лежит в публичном депо Battle.net, как
части карт, а игра держит его в своём кэше (`C:\ProgramData\Blizzard Entertainment\Battle.net\Cache`).
Строки очереди — название, короткое имя, описание — лежат в `.s2ql`, по одной таблице на язык.

## Что есть в Modkit

| Возможность | Где |
| --- | --- |
| Разбор `.s2qh` в модель (очередь, теги, режим, карты) | `modules/game/battlenet/content-sources/queue-header.ts` — `decodeQueueHeader`, `ladderMode` |
| Очередь с названиями из `.s2ql` по депо или кэшу | там же — `readQueueHeader(readComponent, { region, headerHandle, locale, signal })` |
| Кодек `.s2qh`: дерево с именами полей игры и таблица карт пула | `codecs/queue-header` (`blizzard/sc2-queue-header`) |
| Кодек `.s2ql`: строки очереди как XML | `codecs/queue-locale` (`blizzard/sc2-queue-locale`) |
| Живой список очередей региона с маппулами | `BattleNetVfsApi.describeQueues` (`content-sources/vfs-provider.ts`), реализация — `desktop/desktop-backend.ts` |
| Текущий сезон региона (номер, год, даты) | `BattleNetVfsApi.describeSeason`, там же |
| Запросы к сервису игры (MMQGetList, MMQGetInfo, CurrentSeason) | рантайм `artifacts/sc2-publishing-research/queue_wire.py`, методы воркера `queues` и `season` |

Разбор один: кодек и `describeQueues` вызывают один и тот же `decodeQueueHeader`, поэтому просмотр
файла и живой ответ не расходятся. Строки `.s2ql` читает общий `parseLocaleTable` (он же читает
`.s2ml` карт; корень `<locale>` у очередей в нижнем регистре).

Открыть файл: в VS Code — любой `.s2qh` из кэша Battle.net (источник `local:cache`) или с диска;
панель «Таблица» показывает карты пула по ID, «Дерево» — все поля с именами схемы игры.

## `describeQueues`

```ts
const queues = await session.api.describeQueues({ region: 'eu', tags: ['Ladd'], locale: 'ruRU', signal })
// [{ id: 201, version: 163, ladderMode: '1v1', teamSize: 1, teamCount: 2,
//    tags: ['Comp', 'Norm', 'FOS', 'LotV', 'Ladd', 'GMLg', 'Solo'], name: '…', shortName: '1V1',
//    headerHandle: '73327168…', maps: [{ id: 267052, mods: [185978], variantIndex: 0, speed: 'Fasr' }, …] }, …]
```

- `tags` — очереди, у которых есть **каждый** указанный тег (без тегов — все очереди региона, до 64).
  `Ladd` — рейтинговый ладдер.
- `ladderMode` — `1v1`/`2v2`/`3v3`/`4v4` для ладдерной очереди (тег `Ladd`, две команды).
- `version` меняется при каждом изменении очереди — по ней видно смену пула.
- Карты — по Battle.net ID своего региона (у EU, US, KR ID одной карты разные). Названий в файле
  нет: `describeMaps({ maps: [{ id, version: 0 }] })` называет последнюю ревизию.
- Один вызов — один запрос списка, по запросу MMQGetInfo на очередь и чтение заголовков из кэша
  игры или депо (SHA-256 файла сверяется с хэндлом). Пул меняется раз в сезон: кэшируйте ответ.

Бэкенд проверяет ответ воркера: хэндл заголовка должен быть типа `s2qh`, а заголовок — описывать ту
очередь, для которой его назвал сервис.

## `describeSeason`

```ts
await session.api.describeSeason({ region: 'eu', signal })
// { state: 'active', seasonId: 66, number: 2, year: 2026, start: 1782086400, end: 1790000000 }
```

`number` и `year` — как игроки называют сезон («Сезон 2 2026 года»); сервис может их не прислать,
тогда есть только внутренний `seasonId`. `start`/`end` — Unix-секунды. `state: 'roll-in-progress'` —
идёт смена сезона. Бэкенд пропускает только эти поля.

## Формат `.s2qh`

Тот же тегированный формат, что `.s2mh` (`cache-header.ts`); номера полей совпадают с тегами
дескрипторов игры (`bsn/protocol-39ffc80.json`).

| Путь | Поле | Значение |
| --- | --- | --- |
| `0` | `HeaderBase` | общая часть очереди |
| `0.2` | `m_locales` | `[{0: 'enUS', 1: [хэндлы .s2ql]}]` |
| `0.4`, `0.5`, `0.6` | `m_name`, `m_shortName`, `m_description` | `{1: номер таблицы, 2: id строки}` (id 0 — настоящая строка) |
| `0.8`, `0.9` | `m_teamSize`, `m_teamCount` | 1 и 2 у 1v1 |
| `0.11` | `m_premadeTeamsAttribute` | FourCC (`1v1`) |
| `0.14` | `m_tags` | FourCC: `Ladd` ладдер, `Solo`, `Team`, `LotV`, `HotS`, `Comp`, `Coop`, `Trny`, `Mutr`… |
| `0.16` | `m_active` | 1 байт |
| `0.30` | `m_tournamentConfig` | у турнирных очередей — `m_ladderQueue` |
| `0.33` | `m_mapRotationSettings` | ротация карт по времени (мутации) |
| `2` | `m_handle` | `{0: регион, 1: программа 'S2', 3: id очереди, 4: версия}` |
| `3` | `m_maps` | `[MapSpec]` |
| `3[i].0` | `m_link` (`S2Map::Link`) | `{0: вариант, 1: скорость FourCC, 3: [LinkEntry]}` |
| `3[i].0.3[j]` | `LinkEntry` | `{0: {0: ID карты, 1: версия (0 — последняя)}, 1: тип}`; тип 0 — сама карта, остальные — моды расширения |

Регионы: 1 US, 2 EU, 3 KR, 5 CN. В кэше игры на машине разработки (заголовки от 10.06 до 25.09.2026)
очереди EU: 201 — ладдер 1v1, 202 — 2v2, 103 — 3v3 (тег HotS), 301 — турнир 1v1, 275 — кооператив,
291 — мутации (180 карт с ротацией). Это то, что клиент видел последним, а не текущий список.

## Протокол (S2Master, маршрут `S2Ms`)

Тела запросов и разбор ответов проверены эмуляцией кода редактора 5.0.16.97563 бит в бит
(`emulate_queues.py`, тест `test_queue_wire.py`). Контрольных битов у тел ответов нет.

- **MMQGetList** (команда 28): `MatchMaker::Filter` — бит «active есть» [+бит active], 17
  контрольных битов (`rolling_checksum`, начальное состояние 3), бит «теги есть» [+5 бит счётчика,
  FourCC по 32 бита], бит «mmqId есть» [+32 бита]; затем программа (32) и token (32).
  Ответ: token (32), бит результата (0 — успех), 7 бит счётчика и хэндлы очередей (регион 8,
  программа 32, id 32, версия 16) либо ошибка (16).
- **MMQGetInfo** (команда 17): token (32), хэндл очереди (регион 8, программа 32, id 32, версия 16).
  Ответ: allowAgents (1), token (32), бит «очередь есть», затем `QueueInfo` в порядке сборки:
  хэндл `.s2qh` (40 байт с выравниванием), адрес профиля очереди (32 + 64), хэндл очереди.
- **CurrentSeason** (команда 27) — пустое тело. Ответ (читатель `0x7ff7c6367af0`, объект 0xA55C
  байт): бит результата (1 — ошибка 16 бит), `SeasonAuthorityUpdate`: состояние (1), матчмейкеры
  (счётчик 7 бит, по 425 бит), лиги (счётчик 9 бит, по 189 бит), затем `SeasonInfo` в порядке сборки —
  начало (s32), 10 контрольных бит, [reassignLock s32], seasonId (16), [year 16], конец (s32),
  versionedSeasonId (16), version (16), 25 контрольных бит, [number 16], [bonusLock s32],
  [versionedNumber 16], eloMean (64); `[…]` — поле с битом присутствия; s32 передаётся со смещением
  2^31. Дальше конфиги лиг — они не читаются. Раскладка найдена переворотом каждого бита в эмуляции и
  подтверждена: элементы массивов фиксированной длины, все поля сезона попадают на свои места.

## Ограничения

- Живые запросы очередей и сезона проверены эмуляцией, но ещё не на живом сервере: первый прогон —
  через бота (пробы `queues` и `season` диагностики). Если сервер ответит иначе, сырые ответы сохраняет
  `MODKIT_BNET_CAPTURE_DIR`.
- CN: те же запросы, раскладка сборки CN не проверена.
- Сервер фильтрует очереди по тегам сам; `describeQueues` дополнительно оставляет только очереди со
  всеми указанными тегами.
